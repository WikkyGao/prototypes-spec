# 系统参数配置说明规范

## 用途

用于登记系统运行所需的配置参数、默认值、取值范围、生效方式、敏感级别和变更流程。适用于部署配置、环境迁移、参数调优、安全审计和故障排查。

不适用于：

- 业务字典/枚举值维护
- 用户个人偏好设置
- 数据库表结构设计

## 输入与数据来源

| 输入 | 用途 |
|------|------|
| 原型解析 JSON | 配置页面、字段、默认值、控件类型 |
| 部署架构 | 环境、节点、配置中心 |
| 安全基线 | 密码策略、会话、日志、密钥 |
| 运维经验 | 超时、分页、上传限制、备份保留 |

原型中的配置页面字段只能作为“业务参数候选”，不能直接认定为系统参数。参数键名、默认值、取值范围和生效方式必须由开发/运维确认。

## 文档结构

### 1. 引言

- 1.1 编写目的：说明参数配置的登记、变更与审计要求。
- 1.2 适用范围：系统、环境、配置方式。
- 1.3 术语与缩略语：系统参数、业务参数、热加载、重启生效、敏感参数。
- 1.4 参考资料：部署文档、配置中心说明、安全基线。

### 2. 配置概述

- 2.1 配置方式：配置文件、环境变量、配置中心、数据库配置。
- 2.2 环境划分：开发、测试、生产。
- 2.3 生效方式：重启、下次请求、热加载。
- 2.4 配置优先级：环境变量 > 配置中心 > 配置文件 > 默认值（按实际调整）。

### 3. 参数清单

- 3.1 系统基础参数：系统名称、环境、时区、会话、密码策略、上传、分页、日志、备份、接口超时、功能开关。
- 3.2 业务参数：由配置页面字段推断，标注“是否作为系统参数待确认”。
- 3.3 敏感参数：数据库密码、接口密钥、存储凭证、管理员初始密码。

### 4. 配置管理流程

- 4.1 变更申请：申请人、参数、旧值/新值、原因、影响范围。
- 4.2 评审与审批：技术评审、安全评审、业务确认。
- 4.3 实施与验证：变更窗口、备份、灰度、验证指标。
- 4.4 回滚：触发条件、回滚步骤、验证方式。
- 4.5 审计：变更记录、操作人、时间、审批单。

### 5. 环境差异

| 参数 | 开发 | 测试 | 生产 | 差异说明 |
|------|------|------|------|----------|
| 示例 | 待确认 | 待确认 | 待确认 | 按环境填写 |

### 6. 校验与故障处理

- 6.1 配置校验：类型、范围、必填、依赖关系。
- 6.2 常见故障：配置未生效、值越界、密钥错误、环境串用。
- 6.3 排查步骤：确认生效方式 → 检查优先级 → 查看日志 → 回滚。

| 参数名 | 建议使用 `模块.参数` 命名 |
| 分类 | 系统/安全/文件/页面/日志/备份/接口/业务 |
| 说明 | 参数作用 |
| 默认值 | 默认配置；未知写“待确认” |
| 取值范围 | 类型、枚举或数值区间 |

| 敏感 | 是/否 |
| 备注 | 使用场景、依赖、风险 |

### 业务参数

| 列 | 说明 |
|----|------|
| 参数名 | 由页面/字段推断，可能需调整 |
| 所属页面 | 配置页面名称 |
| 说明 | 字段业务含义 |
| 类型 | 从控件或字段类型推断 |
| 默认值 | 原型有默认值时填写，否则“-” |
| 必填 | 是/否/待确认 |
| 备注 | 明确“是否作为系统参数待确认” |

### 敏感参数

| 列 | 说明 |
|----|------|
| 参数/配置 | 敏感项名称，不写明文 |
| 敏感原因 | 可直接访问数据、调用外部系统等 |
| 存储要求 | 密钥管理/加密配置 |
| 脱敏要求 | 日志禁止输出、前端禁止暴露 |
| 轮换要求 | 定期轮换、有效期、首次登录失效 |

## 配置规则

- 参数名使用小写点分命名，避免空格和中文键名。
- 默认值必须是可运行的安全值，生产环境禁止使用示例密钥。
- 敏感参数不得写入文档、日志、前端代码或版本库。
- 同一参数在不同环境取值不同，必须单独登记并说明差异。
- 业务字段是否作为系统参数，必须由业务方和开发共同确认。
- 热加载参数必须说明是否立即影响运行中的请求。
- 参数下线要保留兼容期和迁移说明。

## 便签/备注说明的纳入

- 参数用途、取值范围、默认值说明补入“参数清单”对应行。
- 安全要求、密钥管理、脱敏要求补入“敏感参数”。
- 生效条件、变更窗口、回滚要求补入“配置管理流程”。
- 无法判断归属的备注放入“待确认事项”，不要丢弃。

- [ ] 系统基础参数是否覆盖安全、日志、上传、分页、备份、超时
- [ ] 每个参数是否有默认值、取值范围、生效方式
- [ ] 敏感参数是否脱敏并说明存储/轮换要求
- [ ] 业务参数是否标注“待确认”
- [ ] 环境差异是否清晰
- [ ] 是否有变更、审批、回滚和审计流程
