# 开发计划（md 格式）生成规范

本文件指导如何从原型解析数据生成结构化开发计划 Markdown 文件。当用户要求生成"开发计划"时读取本文件。

## 输出文件

- 文件名：`开发计划.md`
- 位置：原型目录下 `_output/` 或用户指定位置
- 格式：Markdown（`.md`）

## 文档结构

```markdown
# [项目名称] - 开发计划

## 1. 计划信息
- 版本：v1.0
- 日期：YYYY-MM-DD
- 数据来源：原型解析
- 开发周期：N 周（基于功能数量估算）

## 2. 项目概述
基于原型归纳的项目范围、核心模块、技术栈推测

## 3. 模块拆分与排期
按模块（页面）拆分开发任务，标注优先级与依赖关系

## 4. 里程碑计划
按时间节点划分的关键交付节点

## 5. 风险与待确认项
从原型中未明确的部分、需用户补充的内容

## 6. 数据来源说明
```

## 模块拆分表

按页面分组，每页面为一个开发模块：

| 列 | 字段 | 说明 |
|----|------|------|
| 模块名 | 原型页面名 | 对应一个开发模块 |
| 功能数 | 推断的功能数 | 来自功能清单，用于估算工时 |
| 优先级 | P0/P1/P2 | 取该模块最高优先级功能 |
| 预估工时 | 人天 | `功能数 × 0.5~1 人天`（P0 取 1，P1 取 0.5） |
| 依赖模块 | 前置模块名 | 从页面跳转关系推断 |
| 负责角色 | 前端/后端/全栈 | 从控件类型推断（表单→前端，列表→前后端，认证→后端） |
| 备注 | 业务规则/约束 | 来自便签/矩形备注说明 |

**示例**：

| 模块名 | 功能数 | 优先级 | 预估工时 | 依赖模块 | 负责角色 | 备注 |
|--------|--------|--------|---------|---------|---------|------|
| 实例管理 | 6 | P0 | 6 人天 | 概述 | 前后端 | 树形导航需递归接口 |
| 新增节点 | 3 | P0 | 3 人天 | 实例管理 | 前端 | 表单校验规则见备注 |
| 配置中心 | 5 | P0 | 5 人天 | - | 前后端 | - |

## 里程碑划分

按功能优先级和依赖关系划分 4 个里程碑：

| 里程碑 | 时间节点 | 交付内容 | 入口标准 |
|--------|---------|---------|---------|
| M1 - 核心框架 | 第 1-2 周 | 概述页/框架页/认证管理 | 项目启动 |
| M2 - 主功能 | 第 3-5 周 | 实例管理/新增节点/配置中心 | M1 完成 |
| M3 - 配套功能 | 第 6-7 周 | 版本管理/发布/模板列表 | M2 完成 |
| M4 - 优化收尾 | 第 8 周 | 概览/页面跳转/异常处理 | M3 完成 |

**划分原则**：
- P0 功能集中在 M1-M2，确保核心可用
- 有依赖的模块排在依赖模块之后
- 配置/版本/模板等配套功能排 M3
- 概览/边界场景排 M4

## 角色推断规则

| 控件特征 | 推断角色 |
|---------|---------|
| 表单 + 输入框 + 按钮 | 前端（表单页） |
| 表格 + 列表 | 前后端（列表页，需接口） |
| 树形导航 | 前后端（需递归接口） |
| 认证/Token 相关 | 后端 |
| 流程/概述页 | 前端（静态展示） |
| 详情页 | 前后端（需查询接口） |

## 便签/备注说明的纳入

原型解析数据中每页的 `notes` 字段应：

- **补入"备注"列**：业务规则/约束作为模块开发的注意事项
- **影响工时估算**：含复杂业务规则的模块工时上浮 20-50%
- **补入"风险与待确认项"**：无法从原型明确实现的备注作为风险点
- **影响里程碑**：含认证/安全相关备注的模块优先排入 M1

在文档末尾的"数据来源说明"标注：便签/矩形内备注说明已纳入模块备注与风险评估。

## 生成脚本

**对应脚本**：`scripts/generate_dev_plan.py`（可独立执行）。

**用法**：
```bash
# 先用 parse_axure.py 拿到解析 JSON
python3 scripts/parse_axure.py <原型目录> --json > prototype.json

# 再跑生成脚本
python3 scripts/generate_dev_plan.py prototype.json [输出路径]
```

脚本会按本文件的列定义/分组/便签纳入规则生成 `开发计划.md`。若需调整推断逻辑，直接编辑该脚本对应函数。

## 使用要点

1. **工时为估算**：基于功能数和优先级，需团队确认；不要声称是精确排期
2. **依赖关系保守**：仅推断明确的依赖（新增→管理，详情→基础页），其余标"待确认"
3. **里程碑可调**：4 个里程碑为默认划分，用户要求更短/更长周期时调整
4. **风险项诚实**：原型中未明确的都标为风险，不要编造实现方案
5. **备注说明优先**：`notes` 字段影响工时、风险、里程碑排布
6. **不写技术栈**：原型不含技术信息，不要推测具体框架/语言；可留"待技术选型"
