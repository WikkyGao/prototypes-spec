# 服务计划规范

## 用途

用于明确系统上线后的服务范围、组织职责、服务级别（SLA）、服务内容、工作流程、资源保障与持续改进机制，作为运维支持、服务考核和应急响应的依据。

不适用于：

- 项目建设计划/开发排期（应使用开发计划）
- 单次故障处理报告
- 维护手册中的具体操作命令（应使用维护手册）

## 输入与数据来源

| 输入 | 用途 |
|------|------|
| PRD（优先） | 模块、功能、角色、非功能要求与业务边界 |
| 原型解析 JSON | 模块、页面、接口与备注 |
| 维护手册 | 巡检、故障处理、变更与应急要求 |
| 试运行报告 | 问题、风险与上线建议 |
| 服务合同/组织信息 | 团队、联系方式、SLA 与服务窗口 |

**优先基于 PRD**：使用 `generate_spec_docs.py output/PRD.md output/服务计划.md --doc-type service-plan`。原型/PRD 只能说明“服务对象与范围”，不能提供真实人员、联系方式和合同 SLA；这些内容统一写“待确认”。

## 文档结构

### 1. 引言

- 1.1 编写目的：说明用于服务实施、SLA 考核与应急协调。
- 1.2 适用范围：服务覆盖的模块与边界。
- 1.3 术语与缩略语：SLA、P0-P3、RACI、待确认。
- 1.4 参考资料：PRD、维护手册、试运行报告、服务合同。

### 2. 服务概述

- 2.1 服务目标：稳定运行、及时受理、闭环处理、持续改进。
- 2.2 服务对象：业务用户、管理员、运维、外部依赖方。
- 2.3 服务范围：模块表（模块/功能项数/主要功能）。
- 2.4 服务边界：包含/不包含事项及责任边界。

### 3. 服务组织与职责

- 3.1 服务团队角色：服务经理、一线、二线、研发、运维、DBA、安全、供应商。
- 3.2 职责分工：RACI 表（负责/审批/协作/知会）。
- 3.3 沟通与升级机制：一线→二线→研发→管理升级及触发条件。

### 4. 服务内容

- 4.1 实施与上线服务：部署、配置、初始化、上线值守。
- 4.2 培训与推广服务：角色培训、关键用户、操作材料。
- 4.3 日常运维服务：巡检、监控、备份、权限复核、日志审计。
- 4.4 故障响应与恢复：P0-P3 场景、响应/恢复/升级要求。
- 4.5 变更与发布服务：申请、评审、实施、验证、回滚。
- 4.6 数据与安全服务：备份恢复、权限管理、安全事件、合规审计。
- 4.7 巡检与健康检查：应用、数据库、中间件、资源、证书。

### 5. 服务级别（SLA）

- 5.1 服务级别定义：核心服务、一般服务、支持服务。
- 5.2 响应与恢复指标：响应及时率、恢复及时率、可用性、一次解决率、变更成功率。
- 5.3 服务计量与报告：周报、月报、重大事件报告、季度复盘。

### 6. 服务流程

- 6.1 服务受理：受理、分类分级、分派、处理、验证、关闭。
- 6.2 事件分级与处理：按业务影响、用户范围、替代方案分级。
- 6.3 问题管理：重复事件转问题单，根因分析与整改验证。
- 6.4 变更管理：变更单、评审、窗口、验证、回滚。
- 6.5 服务关闭与回访：用户确认、回访、复盘。

### 7. 服务资源与保障

- 7.1 人员与工具：工单、监控、知识库、远程/现场、备件。
- 7.2 风险与应急预案：核心服务不可用、数据损坏、安全事件、人员缺失、第三方故障。

### 8. 服务持续改进

- 工单与 SLA 复盘、高频问题沉淀、文档更新、改进计划与验证。

### 附录

- 待确认事项
- 变更历史
- 数据来源说明

## 表格列定义

### 服务团队角色

| 列 | 说明 |
|----|------|
| 服务角色 | 服务经理/一线/二线/研发/运维/DBA/安全/供应商 |
| 主要职责 | 角色承担的服务职责 |
| 建议人数 | 未知填“待确认” |
| 责任人 | 真实姓名待确认 |

### 故障分级

| 列 | 说明 |
|----|------|
| 故障级别 | P0 重大 / P1 高 / P2 中 / P3 低 |
| 典型场景 | 系统不可用、核心功能异常、一般异常、咨询建议 |
| 响应要求 | 首次响应时限，未约定标“待确认” |
| 恢复要求 | 恢复或提供替代方案的时限 |
| 升级要求 | 升级对象与触发条件 |

### SLA 指标

| 列 | 说明 |
|----|------|
| 指标 | 响应及时率、恢复及时率、可用性、一次解决率、变更成功率 |
| 目标值 | 合同未约定时填“待确认”，可给出建议值但必须标注 |
| 统计口径 | 分子/分母与统计周期 |
| 备注 | 是否扣除维护窗口、是否分级别统计 |

### 服务流程

| 列 | 说明 |
|----|------|
| 步骤 | 受理/分级/分派/处理/验证/关闭 |
| 输入 | 工单、日志、用户反馈等 |
| 处理动作 | 该步骤要做什么 |
| 输出 | 工单、分级结果、处理记录等 |
| 责任方 | 承担该步骤的角色 |

## 便签/备注说明的纳入

- 服务范围、时间窗口、责任边界相关备注优先放入“服务范围”或“服务边界”。
- 巡检、备份、应急相关备注放入“日常运维服务”或“风险与应急预案”。
- 无法判断归属的备注放入“待确认事项”。
- 在“数据来源说明”标注：便签/矩形内备注说明已纳入服务内容或待确认项。

## 质量检查

- [ ] 是否明确服务目标、对象、范围与边界
- [ ] 是否覆盖实施、培训、运维、故障、变更、数据安全
- [ ] 服务团队角色与 RACI 是否完整
- [ ] SLA 是否有指标、口径、目标值且未确认项标注清楚
- [ ] 服务流程是否形成受理到关闭的闭环
- [ ] 是否包含风险、应急预案与持续改进机制
- [ ] 人员、联系方式、合同 SLA 是否标注“待确认”
