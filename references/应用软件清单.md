# 应用软件清单规范

## 用途

用于登记系统交付和运行所需的业务应用、基础软件、中间件、运维工具及其版本、许可、部署位置和责任人。适用于上线交付、软件资产管理、等保/审计和年度盘点。

不适用于：

- 硬件设备清单
- 源代码依赖清单（SBOM）
- 单次采购报价单

## 输入与数据来源

| 输入 | 用途 |
|------|------|
| 原型解析 JSON | 业务模块、页面类型、功能项、接口 |
| 部署架构 | 部署单元、节点、环境 |
| 软件台账 | 名称、版本、许可、供应商 |
| 安全基线 | 版本要求、EOL、补丁要求 |

原型只能推断业务应用模块，不能推断数据库、中间件、操作系统等基础软件。基础软件部分按通用基线给出“建议/待确认”，不得写成已采购或已部署。

## 文档结构

### 1. 引言

- 1.1 编写目的：说明清单用于资产登记、交付验收和版本管理。
- 1.2 适用范围：系统、环境、模块范围。
- 1.3 术语与缩略语：业务应用、基础软件、中间件、许可、EOL。
- 1.4 参考资料：部署文档、采购合同、软件许可证、安全基线。

### 2. 清单说明

- 2.1 编制口径：业务应用与基础软件分开登记。
- 2.2 字段说明：软件名称、类别、版本、用途、部署位置、许可类型、来源、备注。
- 2.3 维护责任：责任人、复核周期、变更更新规则。

### 3. 应用软件清单

- 3.1 基础软件与中间件：数据库、缓存、Web 服务器、消息队列、日志监控、操作系统、容器、CI/CD。
- 3.2 业务应用模块：模块、页面类型、功能项数、主要功能、部署单元。
- 3.3 接口与外部依赖：接口/依赖、类型、说明、确认状态。

### 4. 版本与许可管理

- 4.1 版本管理：台账、升级评估、EOL 跟踪。
- 4.2 许可管理：许可类型、数量、到期时间、续费责任人。
- 4.3 开源合规：许可证类型、义务、风险组件。

### 5. 部署与依赖关系

- 5.1 部署单元：应用、数据库、中间件、工具。
- 5.2 依赖关系：调用方、被调用方、协议、说明。
- 5.3 环境差异：开发、测试、生产版本与部署位置差异。

### 附录

- 待确认事项
- 变更历史
- 软件许可证扫描结果
- 供应商与支持联系方式

## 表格列定义

### 基础软件与中间件

| 列 | 说明 |
|----|------|
| 序号 | 递增编号 |
| 软件名称 | 产品名或通用名称 |
| 类别 | 业务应用/基础软件/中间件/运维工具 |
| 版本 | 已确认版本；未确认写“待确认（建议 X）” |
| 用途 | 在系统中的作用 |
| 部署位置 | 节点、环境或区域 |
| 许可类型 | 开源/商业/自研/待确认 |
| 来源 | 采购、开源、自研、通用基线建议 |
| 备注 | 是否必需、EOL、替代方案 |

### 业务应用模块

| 列 | 说明 |
|----|------|
| 序号 | 递增编号 |
| 应用/模块 | 页面或模块名称 |
| 页面类型 | 管理后台/配置页面/列表页面/流程页面等 |
| 功能项数 | 该模块的功能项数量 |
| 主要功能 | 查看、筛选、新增、编辑、发布等 |
| 部署单元 | 前端/后端/独立服务，待确认 |
| 备注 | 由原型页面推断 |

### 接口与外部依赖

| 列 | 说明 |
|----|------|
| 依赖/接口 | 接口名称或外部系统 |
| 类型 | HTTP/RPC/文件/消息 |
| 说明 | 方法、路径或用途 |
| 确认状态 | 已确认/待确认 |

## 编制规则

- 业务应用模块必须来自原型页面，不凭空增加。
- 基础软件按通用基线列出，但版本、许可、部署位置必须标注“待确认”。
- 同一软件在不同环境版本不一致时，分环境登记或在备注中说明。
- 商用软件必须记录许可数量与到期时间；开源软件必须记录许可证类型。
- 接口推断结果只作为“候选依赖”，不能等同于已确认的外部系统。
- 软件退役、替换、升级都要更新台账并保留变更记录。

## 便签/备注说明的纳入

- 模块用途、部署要求、依赖说明补入“业务应用模块”或“部署与依赖关系”。
- 版本限制、许可约束、EOL 信息补入“版本与许可管理”。
- 外部系统、接口说明补入“接口与外部依赖”。
- 无法判断归属的备注放入“待确认事项”，不要丢弃。

## 质量检查

- [ ] 业务应用模块是否覆盖全部原型页面
- [ ] 基础软件是否区分“已确认”和“建议/待确认”
- [ ] 版本、许可、部署位置、责任人是否可追溯
- [ ] 是否存在 EOL 或高风险未维护组件
- [ ] 接口与外部依赖是否标注确认状态
- [ ] 是否有台账更新与复核机制
