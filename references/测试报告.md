# 功能与性能测试报告规范

## 用途

用于在**同一份文件**中记录功能测试与性能测试的范围、依据、环境、执行结果、缺陷、性能指标、瓶颈分析与上线建议，避免功能报告与性能报告分散。

不适用于：

- 单个缺陷的复现与修复记录
- 只列测试用例、没有执行结果的文档（应使用测试用例）
- 未实际执行的“纸面测试报告”

## 输入与数据来源

| 输入 | 用途 |
|------|------|
| PRD（优先） | 功能项、角色、验收标准、业务规则与非功能要求 |
| 原型解析 JSON | 模块、页面、功能项、接口与备注 |
| 功能清单 | 模块划分、功能优先级 |
| 测试用例 | 用例数、执行结果与缺陷编号 |
| 性能测试脚本与监控 | 并发、响应时间、TPS/QPS、资源使用率 |
| 缺陷管理系统 | 缺陷级别、状态、责任人与修复计划 |

**优先基于 PRD**：使用 `generate_spec_docs.py output/PRD.md output/测试报告.md --doc-type test-report`。PRD 只提供“应测什么”，不能替代真实执行记录；用例执行结果、缺陷、性能指标和结论必须来自测试过程，没有记录时统一写“待执行/待确认”，不得编造通过率或性能数据。

## 文档结构

### 1. 引言

- 1.1 编写目的：说明用于上线决策、缺陷整改与性能优化。
- 1.2 适用范围：测试覆盖的模块与不在范围内的内容。
- 1.3 术语与缩略语：PRD、用例、缺陷、TPS/QPS、P95、待确认。
- 1.4 参考资料：PRD、测试用例、接口文档、监控报表。

### 2. 测试概述

- 2.1 测试目的：功能一致性、接口/数据完整性、性能与稳定性。
- 2.2 测试范围：模块表（模块/功能项数/主要功能）。
- 2.3 测试依据：PRD、功能清单、测试用例、验收标准。
- 2.4 测试环境：应用、版本、数据库、中间件、服务器、客户端、监控。
- 2.5 测试组织与进度：准备、功能测试、性能测试、总结。

### 3. 测试对象与策略

- 3.1 测试对象：功能编号、模块、功能、优先级、验收标准数。
- 3.2 测试类型与策略：功能、接口、权限、兼容性、异常、性能、安全。
- 3.3 测试准入与退出标准：功能与性能分别定义。

### 4. 功能测试报告

- 4.1 功能测试方法：按 PRD 验收标准设计用例，覆盖正常/边界/异常。
- 4.2 用例执行汇总：功能总数、P0/P1/P2、计划/执行/通过/失败/阻塞、通过率。
- 4.3 功能测试结果明细：编号、模块、功能、优先级、执行结果、缺陷编号、备注。
- 4.4 缺陷统计与分析：总数、阻塞/严重/一般/建议、已关闭、遗留。
- 4.5 功能缺陷清单：编号、模块、问题描述、严重级别、状态、责任人、计划修复时间。
- 4.6 功能测试结论：核心功能是否通过、遗留缺陷是否影响上线。

### 5. 性能测试报告

- 5.1 性能测试目标：页面/接口响应时间、吞吐量、并发、错误率、资源水位、稳定性时长。
- 5.2 性能测试场景设计：查询、提交、详情、混合业务、稳定性场景。
- 5.3 测试数据与模型：数据量、分布、压测模型、工具、监控采样。
- 5.4 性能指标汇总：场景、并发、平均/P95 响应时间、TPS/QPS、错误率、结论。
- 5.5 压测结果与趋势：响应曲线、吞吐趋势、资源曲线、拐点。
- 5.6 瓶颈分析与调优建议：数据库、接口、缓存、连接池、资源、前端资源。
- 5.7 性能测试结论：是否达标、是否阻塞上线、优化与验证计划。

### 6. 测试结论与上线建议

- 6.1 综合结论：功能、性能、接口/权限/兼容性测试结论。
- 6.2 遗留问题与风险：影响、应对措施、责任人、计划完成时间。
- 6.3 上线建议：建议上线 / 有条件上线 / 不建议上线，并列出限制条件。

### 附录

- 待确认事项
- 变更历史
- 数据来源说明

## 合并规则

1. 功能测试与性能测试必须写在同一份 `测试报告.md` 中，使用一级章节分开。
2. 功能测试结论与性能测试结论分别给出，最后在“测试结论与上线建议”中汇总。
3. 不得用功能测试结果替代性能测试，也不得在无压测数据时判定性能通过。
4. 任何未执行的用例、未采集的指标、未确认的目标值，均标注“待执行/待确认”。

## 便签/备注说明的纳入

- 业务规则、异常说明优先放入功能测试方法、结果明细或缺陷描述。
- 性能相关约束（并发、数据量、响应要求）放入性能测试目标或场景设计。
- 无法判断归属的备注放入“待确认事项”。
- 在“数据来源说明”标注：便签/矩形内备注说明已纳入测试范围、场景、缺陷或待确认项。

## 质量检查

- [ ] 功能与性能两部分是否在同一文件内且章节完整
- [ ] 测试范围是否覆盖全部 P0/P1 功能
- [ ] 是否明确测试环境、版本、数据与工具
- [ ] 用例执行、缺陷、性能指标是否有真实数据来源
- [ ] 未执行/未采集项是否标注“待执行/待确认”
- [ ] 是否分别给出功能结论、性能结论和综合上线建议
- [ ] 是否列出遗留问题、风险、责任人与计划完成时间
