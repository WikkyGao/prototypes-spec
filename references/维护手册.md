# 维护手册规范

## 用途

用于指导运维团队完成系统日常巡检、故障处理、变更发布、安全合规与应急恢复。适用于系统上线后的运维交接、值班手册和年度维护计划。

不适用于：

- 面向最终用户的功能操作说明（应使用操作手册）
- 开发环境搭建文档
- 单次故障的复盘报告

## 输入与数据来源

| 输入 | 用途 |
|------|------|
| 原型解析 JSON | 模块、页面、功能项、接口、字段 |
| 部署架构 | 应用节点、数据库、中间件、网络区域 |
| 监控与日志 | 指标、告警规则、日志路径 |
| 变更记录 | 版本、发布窗口、回滚包 |
| 安全基线 | 账号、权限、密钥、审计要求 |

原型只能推断“有哪些模块和接口”，不能推断真实部署拓扑、监控工具和值班电话。上述内容统一标注“待确认”，由运维补充。

## 文档结构

### 1. 引言

- 1.1 编写目的：说明手册面向运维、值班与技术支持。
- 1.2 适用范围：系统、环境、模块和不在范围内的内容。
- 1.3 术语与缩略语：P1/P2/P3/P4、RTO、RPO、变更、回滚。
- 1.4 参考资料：部署文档、监控配置、应急预案、安全基线。

### 2. 系统概述

- 2.1 系统架构：架构风格、应用组成、部署方式。
- 2.2 部署拓扑：网络区域、应用节点、数据库节点、负载均衡、备份节点。
- 2.3 依赖组件：前端、后端、数据库、缓存/消息队列、日志/监控。
- 2.4 运行环境：开发、测试、生产环境的地址、版本、用途、负责人。

### 3. 维护组织与职责

- 3.1 角色职责：业务负责人、应用运维、开发、DBA、安全负责人。
- 3.2 值守与响应：服务时间、告警响应时限、升级路径。
- 3.3 升级路径：一线 → 应用负责人 → 开发负责人 → 项目负责人。

### 4. 日常维护

- 4.1 巡检清单：应用进程、接口健康、数据库连接、磁盘、日志、备份、证书。
- 4.2 巡检周期：每日、每周、每月、每季度。
- 4.3 日志与监控：日志路径、保留周期、关键指标、告警阈值。
- 4.4 备份与恢复：备份对象、频率、保留、恢复演练。
- 4.5 账号与权限：账号申请、审批、离岗回收、定期复核。

### 5. 故障处理

- 5.1 故障分级：P1 业务中断、P2 主要功能受损、P3 局部异常、P4 咨询/建议。
- 5.2 常见故障：应用不可用、接口超时、数据库连接失败、磁盘满、证书过期。
- 5.3 处理流程：发现 → 记录 → 初判 → 上报 → 止损 → 修复 → 验证 → 复盘。
- 5.4 升级与通报：升级条件、通报对象、对外口径。

### 6. 变更与发布

- 6.1 变更类型：常规、紧急、配置变更、数据库变更。
- 6.2 变更流程：申请、评审、窗口、实施、验证、回滚、归档。
- 6.3 发布检查：版本包、配置差异、数据库脚本、回滚包、观察指标。
- 6.4 回滚方案：触发条件、回滚步骤、数据回退、验证要点。

### 7. 安全与合规

- 7.1 账号安全：最小权限、双人复核、定期改密。
- 7.2 数据安全：脱敏、加密、导出审批、日志脱敏。
- 7.3 漏洞与补丁：扫描周期、修复时限、例外审批。
- 7.4 审计：操作日志、审计日志保留、异常行为告警。

### 8. 应急预案与演练

- 8.1 应急场景：机房/云区域故障、数据库故障、网络中断、勒索病毒。
- 8.2 应急组织：指挥、技术、业务、沟通角色。
- 8.3 恢复目标：RTO/RPO，待业务确认。
- 8.4 演练计划：频率、范围、记录、改进项。

### 附录

- 待确认事项
- 变更历史
- 联系人清单
- 常用命令与检查脚本

## 表格列定义

### 巡检清单

| 列 | 说明 |
|----|------|
| 检查项 | 应用、数据库、磁盘、日志、备份等 |
| 检查方法 | 命令、平台、接口或人工观察 |
| 正常标准 | 可量化的通过条件 |
| 异常处理 | 发现异常后的第一步动作 |
| 频率 | 每日/每周/每月 |

### 故障分级

| 级别 | 判定标准 | 响应时限 | 通报范围 |
|------|----------|----------|----------|
| P1 | 核心业务中断或数据面临丢失风险 | 15 分钟内 | 项目负责人/业务负责人 |
| P2 | 主要功能受损但有规避方案 | 30 分钟内 | 应用负责人 |
| P3 | 局部功能异常，不影响主流程 | 4 小时内 | 模块负责人 |
| P4 | 咨询、建议、个别用户问题 | 次工作日 | 值班人员 |

### 变更记录

| 列 | 说明 |
|----|------|
| 变更编号 | CHG-001 递增 |
| 变更内容 | 版本、配置、数据库或基础设施 |
| 风险等级 | 高/中/低 |
| 实施时间 | 计划窗口 |
| 验证结果 | 通过/不通过 |
| 回滚状态 | 未触发/已回滚 |

## 维护要求

- 所有生产变更必须有申请、评审、回滚方案和验证记录。
- 紧急变更可先止损，但须在 24 小时内补齐记录。
- 备份必须定期做恢复演练，不能只检查“备份成功”。
- 账号、密钥、证书到期前应提前告警。
- 故障处理以“先恢复、后定位”为原则，避免扩大影响。

## 便签/备注说明的纳入

- 巡检要求、值班安排、联系人等备注优先补入“日常维护”“维护组织与职责”。
- 故障现象、处理经验、临时规避措施补入“故障处理”或“应急预案”。
- 变更约束、维护窗口、回滚注意事项补入“变更与发布”。
- 无法判断归属的备注放入“待确认事项”，不要丢弃。

## 质量检查

- [ ] 是否明确环境、节点、依赖组件和负责人
- [ ] 巡检项是否可执行、有正常标准和异常处理
- [ ] 故障分级与响应时限是否清晰
- [ ] 变更与回滚流程是否可落地
- [ ] 安全、备份、演练是否覆盖
- [ ] 原型未体现的部署信息是否标注“待确认”
