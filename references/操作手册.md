# 操作手册规范

## 用途

用于指导最终用户完成系统登录、页面导航、业务操作、查询筛选和常见问题处理。适用于用户培训、上线交付和日常自助查阅。

不适用于：

- 运维部署、巡检和故障处理（应使用维护手册）
- 开发接口文档
- 业务规则说明书

## 输入与数据来源

| 输入 | 用途 |
|------|------|
| 原型解析 JSON | 页面、按钮、字段、交互、角色 |
| 业务规则 | 操作前置条件、校验规则、状态流转 |
| 权限矩阵 | 角色可见页面与可操作按钮 |
| 用户反馈 | 高频问题、易错步骤 |

原型中的交互可能包含原型运行时噪声（显示/隐藏、移动、旋转、JavaScript 动作），操作手册只保留用户可理解的导航、按钮和表单动作。

## 文档结构

### 1. 引言

- 1.1 编写目的：说明手册面向最终用户。
- 1.2 适用范围：系统、角色、页面范围。
- 1.3 术语与缩略语：模块、字段、待确认。
- 1.4 参考资料：业务规则、权限矩阵、培训材料。

### 2. 系统访问

- 2.1 访问地址：各环境地址，待确认。
- 2.2 登录步骤：打开地址、输入账号密码、验证码/单点登录、进入首页。
- 2.3 退出与切换账号：安全退出、清除会话。
- 2.4 浏览器与分辨率：推荐浏览器、最低分辨率。

### 3. 角色与权限

- 3.1 角色说明：角色、可见模块、主要操作。
- 3.2 权限申请：申请流程、审批人、生效时间。
- 3.3 无权限处理：提示含义、联系管理员。

### 4. 功能操作

按页面/模块组织，每个功能包含：

- 功能说明：页面用途、包含的功能项。
- 操作步骤：进入页面、选择条件、填写表单、提交。
- 字段说明：字段、类型、必填、默认值、说明。
- 结果与异常：成功、失败、无权限。

### 5. 常见业务场景

用“场景 → 涉及模块 → 操作步骤 → 预期结果”描述跨页面流程，例如查询浏览、新增编辑、配置发布、认证登录。

### 6. 常见问题

| 问题 | 可能原因 | 处理方式 |
|------|----------|----------|
| 无法登录 | 账号密码错误、账号锁定、网络不通 | 核对账号、联系管理员解锁、检查网络 |
| 页面空白/加载失败 | 缓存、浏览器兼容、服务异常 | 刷新/清缓存/更换浏览器，仍失败联系运维 |
| 查询无数据 | 筛选条件过严、数据未同步 | 放宽条件、清空筛选、确认数据状态 |
| 保存失败 | 必填项缺失、格式错误、无权限 | 按提示修正、检查权限 |
| 操作按钮不可见 | 角色权限不足 | 联系管理员分配权限 |

### 7. 使用说明

- 7.1 术语：模块、字段、待确认。
- 7.2 使用建议：确认环境与权限、批量操作先小范围验证、异常记录页面/时间/步骤/提示。

### 附录

- 待确认事项
- 变更历史
- 快捷操作与键盘说明（如有）

## 写作规则

### 操作步骤

- 使用“进入 → 选择 → 填写 → 提交 → 查看结果”的顺序。
- 每一步只描述一个动作，避免长句。
- 按钮名称、菜单名称、字段名称使用页面原文，并用「」标注。
- 原型中的“打开某页面”改写为“在导航中打开「某页面」”。
- 不写“Click时”“MouseOver时”等原型事件名。
- 不写显示/隐藏、移动、旋转、选中状态等 UI 特效。
- 没有按钮和表单时，给出通用步骤，不编造具体按钮。

### 字段说明

| 列 | 说明 |
|----|------|
| 字段 | 页面标签或表格列名 |
| 类型 | 从控件推断；无法判断写“待确认” |
| 必填 | 是/否/待确认 |
| 默认值 | 原型有默认值时填写，否则“-” |
| 说明 | 业务含义、格式、取值范围 |

### 结果与异常

每个功能至少覆盖：

- 成功：提示、页面变化、数据刷新。
- 失败：保留输入、提示原因、重试方式。
- 无权限：提示内容、申请路径。

## 便签/备注说明的纳入

- 业务规则、前置条件、校验说明优先补入对应功能的“操作步骤”或“结果与异常”。
- 用户易错点、常见问题补入“常见问题”。
- 角色差异、权限限制补入“角色与权限”。
- 无法判断归属的备注放入“待确认事项”，不要丢弃。

## 质量检查

- [ ] 登录、退出、权限说明是否完整
- [ ] 每个页面是否有功能说明、操作步骤、字段说明、结果与异常
- [ ] 操作步骤是否使用用户语言，是否过滤原型噪声
- [ ] 跨页面场景是否覆盖主流程
- [ ] 常见问题是否来自真实高频问题
- [ ] 原型未体现的内容是否标注“待确认”
