# 培训计划规范

## 用途

用于规划系统上线前/新版本推广时的培训目标、对象、课程、组织、日程与考核安排，作为培训实施、效果评估和上线准备的依据。

不适用于：

- 系统功能说明书（应使用操作手册/详细说明书）
- 单次培训会议纪要
- 没有明确培训对象的通用宣贯材料

## 输入与数据来源

| 输入 | 用途 |
|------|------|
| PRD（优先） | 功能项、角色、字段、业务规则与验收标准 |
| 原型解析 JSON | 模块、页面、功能项、控件与备注 |
| 功能清单 | 模块划分与功能优先级 |
| 操作手册/测试用例 | 操作步骤、常见问题与演练场景 |
| 培训组织信息 | 时间、地点、讲师、人数与考核要求 |

**优先基于 PRD**：使用 `generate_spec_docs.py output/PRD.md output/培训计划.md --doc-type training-plan`，功能项、角色和优先级从 PRD 解析。仅有原型解析 JSON 时也可生成，但需在输出中说明功能项来自原型推断。

原型/PRD 只能说明“培训什么”，不能提供真实培训时间、讲师和考核结果；这些内容统一写“待确认”。

## 文档结构

### 1. 引言

- 1.1 编写目的：说明用于培训实施与效果评估。
- 1.2 适用范围：培训覆盖的模块与不在范围内的内容。
- 1.3 术语与缩略语：PRD、模块、字段、P0/P1/P2、待确认。
- 1.4 参考资料：PRD、操作手册、功能清单、测试用例。

### 2. 培训概述

- 2.1 培训目标：围绕“能独立操作、理解规则、会处理异常”展开。
- 2.2 培训对象：角色、职责、涉及模块、人数。
- 2.3 培训范围：模块表（模块/功能项数/主要功能）。
- 2.4 培训前提与约束：环境、账号、教材、时间、数据合规。

### 3. 培训需求分析

- 3.1 角色能力矩阵：角色、能力要求、重点功能、建议课时。
- 3.2 模块培训需求：模块、功能项数、核心功能、培训方式、建议课时。
- 3.3 培训重点与难点：高频核心功能、配置与权限、易错规则、异常处理、数据安全。

### 4. 培训内容与课程安排

- 4.1 课程大纲：课程编号、课程名称、覆盖模块、培训要点、课时、培训方式。
- 4.2 分角色课程组合：必修、选修、考核方式。
- 4.3 操作演练场景：场景、涉及模块、操作要点、预期结果。

### 5. 培训组织与实施

- 5.1 培训方式：集中授课、在线演示、实操演练、一对一辅导、文档自学。
- 5.2 讲师与教材：讲师来源、教材、演示环境、培训记录。
- 5.3 培训环境与数据：应用地址、账号、脱敏数据、网络。
- 5.4 培训日程：阶段、计划时间、对象、内容、讲师。

### 6. 考核与效果评估

- 6.1 考核方式：实操、笔试/问卷、现场问答。
- 6.2 合格标准：核心场景独立完成、理解字段与规则、按流程反馈问题。
- 6.3 效果评估指标：覆盖率、通过率、上线后操作类问题数、满意度、关键用户覆盖率。

### 7. 培训保障与风险

- 7.1 组织保障：负责人、讲师、关键用户、考勤与归档。
- 7.2 风险与应对：时间不足、环境不可用、角色覆盖不全、规则变化、数据不合规。

### 附录

- 待确认事项
- 变更历史
- 数据来源说明

## 表格列定义

### 培训对象

| 列 | 说明 |
|----|------|
| 角色 | PRD/原型识别的用户角色 |
| 职责 | 角色的业务职责 |
| 主要涉及模块 | 按权限裁剪后的模块 |
| 人数 | 实际人数，未知填“待确认” |

### 模块培训需求

| 列 | 说明 |
|----|------|
| 模块 | PRD 模块或原型页面 |
| 功能项数 | 该模块功能项数量 |
| 核心功能 | 功能名称，最多列 4-5 项 |
| 培训方式 | 讲解+演示+实操等 |
| 建议课时 | 按功能项数量给出的建议值，必须标注“待确认” |

### 课程大纲

| 列 | 说明 |
|----|------|
| 课程编号 | TR-01 递增 |
| 课程名称 | 模块名 + 功能培训 |
| 覆盖模块 | 对应模块 |
| 培训要点 | 功能名称或关键操作 |
| 课时 | 待确认 |
| 培训方式 | 讲解/演示/实操/自学 |

### 效果评估指标

| 列 | 说明 |
|----|------|
| 指标 | 覆盖率、通过率、问题数、满意度等 |
| 目标值 | 未确认时填“待确认” |
| 数据来源 | 签到表、考核记录、工单、问卷 |
| 备注 | 统计口径 |

## 便签/备注说明的纳入

- 业务规则、操作约束优先放入“培训重点与难点”或“操作演练场景”。
- 权限、角色、数据范围相关备注放入“培训对象”或“培训重点”。
- 无法判断归属的备注放入“待确认事项”。
- 在“数据来源说明”标注：便签/矩形内备注说明已纳入培训内容或待确认项。

## 质量检查

- [ ] 是否明确培训目标、对象、范围和前提
- [ ] 是否覆盖全部 P0/P1 功能及配置/权限场景
- [ ] 课程是否按角色可组合，课时是否标注待确认
- [ ] 是否有考核方式、合格标准和效果评估指标
- [ ] 是否说明培训环境、数据脱敏与记录归档要求
- [ ] 所有未确认的时间、人数、讲师是否标注“待确认”
