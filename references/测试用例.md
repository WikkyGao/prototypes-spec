# 测试用例（xlsx 格式）生成规范

本文件指导如何从原型解析数据生成结构化测试用例 Excel 文件。当用户要求生成"测试用例"且需要 xlsx 格式时读取本文件。

## 输出文件

- 文件名：`测试用例.xlsx`
- 位置：原型目录下 `_output/` 或用户指定位置
- 格式：Excel `.xlsx`，使用 `openpyxl` 库生成

## 工作表结构

### 主表「测试用例」

按模块分组组织，每组首行为模块标题行（合并单元格 + 蓝色填充），后续为该模块的用例。

**列定义**（8 列，固定顺序）：

| 列 | 字段 | 宽度 | 说明 |
|----|------|------|------|
| A | 用例编号 | 14 | 格式 `TC-XXX`，三位序号，全局递增 |
| B | 模块 | 18 | 所属功能模块名（来自页面或控件分组） |
| C | 功能点 | 20 | 具体被测功能点 |
| D | 用例标题 | 28 | 一句话概括测试场景 |
| E | 前置条件 | 28 | 执行前必须满足的条件（已登录/有数据/已进入页面等） |
| F | 测试步骤 | 40 | 编号步骤，每步一行（单元格内换行 `\n`） |
| G | 预期结果 | 36 | 每步对应的预期结果，与步骤一一对应 |
| H | 优先级 | 8 | P0（核心）/ P1（重要）/ P2（一般）/ P3（边界） |

**示例行**：

| A | B | C | D | E | F | G | H |
|---|---|---|---|---|---|---|---|
| TC-001 | 实例管理 | 实例列表加载 | 正常加载列表 | 已登录系统 | 1. 进入实例管理页 | 显示所有服务实例，含名称/版本/状态/IP | P0 |
| TC-002 | 新增节点 | 表单提交 | 必填项为空提交 | 已登录系统 | 1. 进入新增节点页 2. 不填必填项 3. 点击确定 | 提示必填项不能为空 | P0 |

### 副表「说明」

第二张工作表，记录文档元信息：

| 字段 | 内容 |
|------|------|
| 项目名称 | 原型项目名 |
| 生成日期 | YYYY-MM-DD |
| 数据来源 | 原型工具类型（Axure/墨刀/MasterGo/蓝湖） |
| 用例总数 | N |
| 备注 | 「备注说明」字段来自原型便签/矩形备注，已合并入用例描述 |

## 用例设计原则

1. **覆盖优先**：每个页面的主要功能至少 1 个 P0 用例
2. **边界优先**：表单类功能必须补必填项为空、格式错误等边界用例（P3）
3. **步骤可执行**：每步必须是用户可独立完成的操作（进入页面/点击按钮/填入文本）
4. **结果可验证**：预期结果需明确可观测（显示/跳转/提示/禁用）
5. **不编造**：原型中未体现的功能不设计用例，标注「（待补充）」

## 便签/备注说明的纳入

原型解析数据中每页的 `notes` 字段（便签/矩形内备注说明）应：

- 作为该页面相关用例的**补充前置条件**或**额外预期结果**写入
- 若备注说明的是业务规则（如"Access Token 有效期 24 小时"），补为对应功能的边界用例
- 若备注说明的是数据约束（如"跨 VLAN 调用验证不通过"），补为异常场景用例
- 在副表「说明」的「备注」字段标注已纳入

## 生成脚本

**对应脚本**：`scripts/generate_test_cases.py`（可独立执行）。

**用法**：
```bash
# 先用 parse_axure.py 拿到解析 JSON
python3 scripts/parse_axure.py <原型目录> --json > prototype.json

# 再跑生成脚本
python3 scripts/generate_test_cases.py prototype.json [输出路径]
```

脚本会按本文件的列定义/分组/便签纳入规则生成 `测试用例.xlsx`。若需调整推断逻辑，直接编辑该脚本对应函数。

## 使用要点

1. **不要用 pandas**：直接用 `openpyxl`，避免依赖；单元格内换行用 `\n` + `wrap_text=True`
2. **合并单元格做模块标题**：`ws.merge_cells()`，样式与表头区分
3. **列宽固定**：按上表设置，避免内容挤压
4. **冻结首行**：`ws.freeze_panes = 'A2'`，长列表可滚动
5. **用例编号全局递增**：不按模块重置，便于跨模块引用
