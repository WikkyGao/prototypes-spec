# 数据字典（md 格式）生成规范

本文件指导如何从原型解析数据生成结构化数据字典 Markdown 文件。当用户要求生成"数据字典"时读取本文件。

## 输出文件

- 文件名：`数据字典.md`
- 位置：原型目录下 `_output/` 或用户指定位置
- 格式：Markdown（`.md`）

## 文档结构

```markdown
# [项目名称] - 数据字典

## 1. 文档信息
- 版本：v1.0
- 日期：YYYY-MM-DD
- 数据来源：原型解析（工具类型标注）

## 2. 字段总览
按所属页面分组的字段清单（本节为概览，详见各页面章节）

## 3. 字段定义详表

### 3.1 [页面 A 名称]

| 字段名 | 中文名 | 类型 | 长度 | 必填 | 默认值 | 说明 | 所属页面 | 备注 |
| ... |

### 3.2 [页面 B 名称]
...

## 4. 枚举值定义
从原型文本中提取的可能枚举字段及其候选值

## 5. 关联关系
字段间的引用关系（如"实例 IP"关联"实例名称"）
```

## 字段定义表（9 列）

| 列 | 字段 | 说明 |
|----|------|------|
| 1 | 字段名 | 英文驼峰命名，从中文推断（如"实例名称" → `instanceName`） |
| 2 | 中文名 | 原型中的字段标签原文 |
| 3 | 类型 | string / integer / boolean / datetime / enum / text（长文本） / json |
| 4 | 长度 | 推断长度（无明确标注时留"-"） |
| 5 | 必填 | 是 / 否（表单中的必填项标记） |
| 6 | 默认值 | 原型中预填的默认值（无则"-"） |
| 7 | 说明 | 字段用途描述，**优先使用原型中的备注说明** |
| 8 | 所属页面 | 字段出现的页面名 |
| 9 | 备注 | 补充信息（约束/校验规则/关联字段，来自便签/矩形备注） |

**示例行**：

| 字段名 | 中文名 | 类型 | 长度 | 必填 | 默认值 | 说明 | 所属页面 | 备注 |
|--------|--------|------|------|------|--------|------|----------|------|
| instanceName | 实例名称 | string | 50 | 是 | - | 服务实例的唯一标识 | 实例管理 | 创建后不可修改 |
| version | 版本 | string | 20 | 是 | - | 服务版本号 | 页面1 | - |
| status | 状态 | enum | - | 是 | running | 运行状态 | 页面1 | 候选：running/stopped/error |
| serverIP | 服务器IP | string | 15 | 是 | - | 服务器 IP 地址 | 页面1 | IPv4 格式 |

## 字段推断规则

从原型解析数据推断字段时遵循以下顺序：

1. **表格控件**：表格列标题 → 字段中文名，每列一个字段
2. **输入框/文本框**：输入框前标签 → 字段中文名，输入框类型 → 字段类型
3. **下拉列表**：标签 → 字段中文名，类型为 `enum`，候选值从下拉项提取
4. **复选框/单选按钮**：标签 → 字段中文名，类型为 `boolean` 或 `enum`
5. **树形节点**：树节点文本 → 分组字段，子节点为枚举值
6. **矩形内文本段落**：含"标签：值"格式的文本 → 字段定义
7. **备注说明**：`notes` 字段中的备注 → 字段的"备注"列

**类型推断规则**：

| 原型特征 | 推断类型 |
|---------|---------|
| 输入框（短） | `string` |
| 多行文本框 | `text` |
| 数字输入框 | `integer` |
| 日期选择器 | `datetime` |
| 下拉列表 | `enum` + 候选值 |
| 复选框 | `boolean` |
| 单选按钮组 | `enum` + 候选值 |
| 含 IP 格式文本 | `string` + 备注"IPv4 格式" |
| 含时间格式文本 | `datetime` |
| JSON 结构文本 | `json` |

**字段名命名规则**（中文 → 英文）：

- 用拼音或通用英文翻译（如"实例名称" → `instanceName`）
- 驼峰命名，首字母小写
- 避免缩写歧义（如 `ip` 用 `serverIP` 明确）
- 同一字段在多页面出现时保持同名

## 便签/备注说明的纳入

原型解析数据中每页的 `notes` 字段应：

- **优先填入"说明"列**：备注说明通常比字段标签更具描述性
- **约束规则填入"备注"列**：如"有效期 24 小时"→ 对应 token 字段的备注
- **校验规则填入"备注"列**：如"跨 VLAN 调用验证不通过"→ 关联字段的备注
- **枚举值补充**：备注中提及的候选状态补入对应 enum 字段的候选值

在文档末尾的"数据来源说明"标注：便签/矩形内备注说明已纳入字段定义。

## 生成脚本

**对应脚本**：`scripts/generate_data_dict.py`（可独立执行）。

**用法**：
```bash
# 先用 parse_axure.py 拿到解析 JSON
python3 scripts/parse_axure.py <原型目录> --json > prototype.json

# 再跑生成脚本
python3 scripts/generate_data_dict.py prototype.json [输出路径]
```

脚本会按本文件的列定义/分组/便签纳入规则生成 `数据字典.md`。若需调整推断逻辑，直接编辑该脚本对应函数。

## 使用要点

1. **按页面分组**：字段按所属页面组织，便于开发对照原型
2. **去重保留首次**：同一字段在多页面出现时保留首次定义，备注合并
3. **类型推断保守**：无法确定时用 `string`，避免误判
4. **标注推测值**：长度/必填为推测时在备注列说明
5. **备注说明优先**：`notes` 字段内容优先于字段标签填入"说明"列
